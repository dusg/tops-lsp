# 契约：补全候选的语法规则与可见性

这份文档把“根据语法规则和语义可见性给候选”变成可以照着实现、照着测试的规则表。

## 1. 处理流程

1. 换算光标偏移；位置非法 → `InvalidParams`。
2. 如果没有新鲜结果：分析进行中 → 返回一条“正在分析”提示项；否则 → 返回空名单。
3. 判断光标是否在“不产生候选”的区域（见第 2 节）。
4. 判断光标处的语法位置（见第 3 节）。
5. 收集该语法位置允许、且语义可见的名字（见第 4 节）。
6. 计算替换范围与过滤文本（见第 5 节）。
7. 去重、排序、生成补全项（见第 6 节）。

## 2. 不产生候选的区域

| 区域 | 判断依据 | 结果 |
|------|----------|------|
| 注释 | 光标落在注释 token 范围内 | 空名单 |
| 字符串、字符字面量 | 光标落在字面量 token 范围内 | 空名单 |
| 预处理指令行 | 光标落在 `NodePreprocessorDirective.DirectiveRange` 内 | 空名单 |
| 头文件包含路径 | `#include` 的目标范围内 | 空名单 |
| 宏条件不可判定区域 | 光标所在位置的条件状态为“未知” | 空名单 |

## 3. 语法规则表

“光标处情况”统一按**光标前一个非空白 token** 判定，判定顺序从上到下，第一条命中即停止。行首（光标前没有任何非空白 token）视为“声明开头”。

| 光标处情况 | 判定条件（前一 token） | 允许的候选类别 |
|------------|------------------------|----------------|
| 标识符前缀中间或末尾（默认情况） | 标识符、数字、`)`、`]`、`>` | 可见符号、关键字、Tops 关键字、宏 |
| 声明开头 | 无（行首）、`;`、`{`、`}`、`:`（标签或访问说明符） | 关键字、Tops 关键字、可见的类型与函数名 |
| 属性位置 | `[[` 或当前前缀以 `__` 开头 | Tops 关键字、属性符号 |
| 类型位置 | 声明符前的类型片段位置，或前一 token 为类型关键字 | 可见类型符号、关键字、`__vector` 等 Tops 类型关键字 |
| 点号或箭头之后 | `.`、`->` | 空名单（成员访问不在本版范围） |
| 作用域解析符之后 | `::` | 可见命名空间与类型名 |
| 表达式位置 | 运算符、`(`、`,`、`=`、`return`、`case` 等 | 可见变量、函数名、宏、关键字 |

**说明**：

- “声明开头”必须有可判定的 token 依据，不能按行首字符或空白数量推断。
- `:` 既可能是标签、`case` 后的冒号，也可能是访问说明符或位域分隔符；本版统一按“声明开头”处理，属于可接受的简化。
- 本版规则表只区分“允许哪类名字”，不做完整表达式语法分析。落在表外的情况按“默认情况”处理。

## 4. 语义可见性

可见名字集合由以下部分组成：

1. 包含光标的最内层作用域中的符号。
2. 沿父作用域向上直到翻译单元，逐层加入。
3. 翻译单元级符号与头文件级符号（`ScopeTranslationUnit`、`ScopeHeader`）。
4. 编译上下文提供的预定义宏（`IndexSnapshot.PredefinedMacros`）。

排除规则：

| 情况 | 处理 |
|------|------|
| 条件状态为“无效”（`ConditionalInactive`）的符号 | 排除 |
| 条件状态为“未知”的符号 | 保留，但悬停要标明降级 |
| 符号状态为 `stale` | 排除 |
| 声明在光标之后且同作用域内不可见的局部变量 | 排除（按作用域声明顺序判断） |
| 重复名字（同名同种类同范围） | 合并为一条 |
| 内置变量的可用性不是 `available` | 排除 |

## 5. 替换范围与过滤文本

| 项 | 规则 |
|----|------|
| 前缀 | 从光标向前连续取标识符字符（字母、数字、下划线） |
| `textEdit.range` | 前缀的起止位置；前缀为空时是光标处的空范围 |
| `textEdit.newText` | 候选名字 |
| `filterText` | 候选名字（提示项用当前前缀） |

## 6. 去重与排序

**去重键**：`名字 | 种类 | 来源地址`。

**排序**：

1. 名字前缀匹配的候选在前（前缀是候选名字的前缀），其余在后。
2. 同组内按种类优先级：变量/函数/类型/命名空间/宏/关键字。
3. 再按名字字典序升序。

**`sortText`**：用三位数字前缀编码组序与序号，保证客户端排序与服务器顺序一致。

- `000` 保留给“正在分析”提示项；该场景下不返回真实候选，因此不会与真实候选冲突。
- 真实候选从 `001` 起编号：组序（前缀匹配 / 其余）占首位，序号在后两位。
- 同一输入必须产生完全相同的 `sortText` 序列。

## 7. 补全项字段

| 字段 | 规则 |
|------|------|
| `label` | 符号名字或关键字拼写 |
| `kind` | 按 [data-model.md](../data-model.md) 第 4 节的映射表 |
| `detail` | 已知类型、签名或来源说明 |
| `textEdit` | 见第 5 节 |
| `filterText` | 见第 5 节 |
| `sortText` | 见第 6 节 |
| `data` | `source`（`index` / `semantic` / `keyword` / `predefined-macro`）、`profileId`、`passKind`、`contextStatus` |

## 8. 边界行为

| 情况 | 结果 |
|------|------|
| 文件为空 | 关键字与可见符号（可能为空） |
| 光标在文件末尾 | 正常生成候选，替换范围为光标处空范围 |
| 光标在最后一个字符之后一行 | 正常生成候选 |
| 当前正在输入一个名字的一部分 | 替换范围覆盖该部分 |
| 当前输入以 `__` 开头 | 增加 Tops 关键字与属性 |
| 分析进行中 | 只返回一条提示项 |

## 9. 明确不做

以下场景本版返回空名单，不报错：

- 成员访问（`.`、`->`）
- 自动导入
- 代码片段
- 重载排序
- 文档渲染
- 跨仓库符号搜索
- 补全项二次解析（`completionItem/resolve`）
